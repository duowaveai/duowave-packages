# Каталог пакетов DuoWave

> Как сделать своего персонажа — коротко, с примерами: [docs/character.md](docs/character.md).

Общий каталог пакетов для голосового шлюза DuoWave: сейчас — персонажи, со временем — темы пульта, плагины и
приложения. Вид пакета — поле `kind`; в каталоге только то, что проверено нами (`verified`).

Каталог — статика, сервера нет: лента `catalog.json`, архивы пакетов `.vgp`, превью (картинка и фразы) и страница-
галерея. Шлюз скачивает ленту, показывает каталог в пульте и ставит пакет только по кнопке человека с правом — сам
ничего не ставит и не обновляет. Замысел и формат — `docs/plans/characters.md` в репозитории шлюза (разделы 1–3, 7 и
«Контракт API»); этот репозиторий — его этапы 1 и 6.

## Что внутри

```
packages/<id>/            пакет: то, что попадёт в архив
  manifest.json           кто это, характер, регуляторы тона, голос
  assets/                 аватар, фразы-пробники, снимки голоса, образец голоса
art/<id>.svg              исходник аватара (в пакет не идёт: SVG в пакетах нельзя)
voices.json               описание голоса каждого персонажа для tools/design.py
schemas/                  JSON Schema: ленты (catalog.schema.json) и манифеста персонажа
tools/
  check.mjs               проверка пакетов (её же вызывает сборка)
  build.mjs               сборка dist/: архивы, превью, хеши, catalog.json, сайт
  tar.mjs                 tar.gz без зависимостей, одинаковый от сборки к сборке
  avatars.mjs             art/<id>.svg → packages/<id>/assets/avatar.webp
  design.py               голоса по описанию (OmniVoice) → снимки и фразы в пакет
site/                     страница каталога (HTML, CSS, JS без фреймворков); сборка кладёт её в dist/
dist/                     результат сборки, в git не хранится
work/                     черновики голосов (варианты, отпечатки), в git не хранится
```

## Пакет персонажа

Обычный пакет шлюза без кода: `manifest.json` и `assets/`. Схема — `schemas/character-manifest.schema.json`, пример —
любой из `packages/*/manifest.json`. Коротко:

- `schema: 1`, `kind: "character"`, `id` (как папка), `version` (semver), `api: "^1"`, `title`, `description`,
  `runs` (`pc`, `station`, `stationServer`), `license`;
- `contributes.characters` — список (обычно один персонаж): `id`, `gender` (`male` | `female` | `any`), `color`,
  `avatar`, `prompt`, `tones`, `samples`, `fallbackVoice`, `voices`, `ref`, `voiceOrigin` (`synthetic` | `consent`);
- `tones` — регуляторы: у каждого 2–5 положений, каждое подставляет в промт одну строку `line`; `default` — номер
  положения с нуля;
- `voices` — снимки голоса по id модели (`omnivoice`, `cosyvoice3`): `{file, model}`, где `model` — ревизия весов;
  `ref` — образец WAV и его слова, из которых шлюз переснимет голос под другую ревизию.

Пределы (проверяет `tools/check.mjs`): промт — до 4000 знаков; аватар — WebP или PNG, квадрат, до 256 КБ; фраз-
пробников — не больше трёх, Opus до 64 КБ каждая; пакет целиком — меньше 1 МБ; все пути — внутри `assets/`, без `..`
и ссылок; SVG нельзя; только `manifest.json` и `assets/` — никакого кода; в текстах нет «Алисы» и «Яндекса».

Промт описывает только персонажа: кто он, как говорит, в каком роде, чего никогда не делает. Строку про слово-
активацию колонки и правила речи (коротко, без списков, числа словами) шлюз добавляет сам.

## Как добавить персонажа

1. Скопируйте папку любого персонажа в `packages/<id>/` (id — строчные латинские буквы, цифры и «-», с буквы) и
   перепишите `manifest.json`: id, тексты, цвет, регуляторы, запасной голос подходящего пола. Голоса — пустые:
   `"samples": []`, `"voices": {}`, без `ref`.
2. Нарисуйте аватар в `art/<id>.svg` (512×512, своя графика — никаких чужих персонажей и реальных людей) и
   переведите в WebP: `node tools/avatars.mjs <id>`. ImageMagick рисует обводки, только если у них явно указано
   `stroke-opacity="1"`.
3. Опишите голос в `voices.json`: `instruct`, фраза образца `reference`, три фразы `samples`.
4. Проверьте и соберите: `node tools/build.mjs`. Ошибки названы словами — поправьте и повторите.
5. Pull request. Голос делается отдельно (ниже) — пакет без голоса тоже годен.

## Голоса персонажей: `tools/design.py`

Голоса синтетические — по описанию, ничьи. Модель — OmniVoice в режиме voice design: описание вида
`male, elderly, low pitch` (пол, возраст, высота голоса, шёпот, акцент) → десяток вариантов одной фразы → лучший на
слух становится образцом → `clone-server/imprint.py` шлюза снимает с него снимки под каждую модель.

Нужно: шлюз рядом (`../voice-gateway-server`) с установленной моделью OmniVoice (пульт шлюза → «Модели» → «Голос»);
для снимка под CosyVoice 3 — и она; `ffmpeg` с libopus. Работает на видеокарте Мака (MPS) или NVIDIA, занимает минуты
и несколько гигабайт памяти. Запускается окружением модели — своих зависимостей у скрипта нет:

```bash
CS=../voice-gateway-server/clone-server          # или --clone-server / CLONE_SERVER
PY=$CS/runtime/omnivoice/env/bin/python

# 1. варианты: 10 штук фразы образца из voices.json → work/arthur/candidates/
$PY tools/design.py candidates arthur
$PY tools/design.py candidates arthur --instruct "male, elderly, moderate pitch" --count 5   # ещё, с другим описанием
open work/arthur/index.html                      # послушать; у каждого — длина и годится ли он в образец

# 2. выбранный вариант → пакет
$PY tools/design.py adopt arthur 7

# 3. послушать packages/arthur/assets/samples/*.opus, собрать, закоммитить
node tools/build.mjs
```

`adopt` делает:

- снимки `imprint.py` под каждую установленную модель (`omnivoice`, `cosyvoice3`; `--engines` — выбрать самому), на
  процессоре — так вдвое меньше памяти (`--imprint-device`); образцом берётся весь вариант целиком, его слова уже
  известны — распознавание не нужно (imprint.py спрашивает их у маленького сервера слов внутри design.py);
- `assets/voices/ref.wav` — тот кусок, с которого сняты снимки, `assets/voices/<модель>.pt` — снимки;
- до трёх фраз-пробников голосом первой модели → `assets/samples/N.opus`;
- в манифесте — `voices` (файл и ревизия весов: OmniVoice — из кеша HuggingFace, CosyVoice 3 — коммит его
  репозитория), `ref` (файл и слова), `samples`; в `voices.json` — `adopted`: номер, зерно и описание варианта.

Модели, которой нет на этом компьютере, в пакете не будет — шлюз снимет снимок сам из `ref.wav`, когда она встанет.
Варианты повторяемы: у каждого своё зерно (`--seed`), разнообразие — `--temperature`, темп — `--speed`. Уже
опубликованному пакету с новым голосом — новая `version`.

## Сборка

```bash
node tools/build.mjs            # проверить пакеты и собрать dist/
node tools/build.mjs --check    # только проверить
node tools/check.mjs            # то же, с выбором пакетов: node tools/check.mjs packages/arthur
```

Нужен только Node 18+ — зависимостей нет. Пакет с ошибкой не собирается, и каталог целиком тоже. Результат:

```
dist/
  catalog.json                       лента (схема — schemas/catalog.schema.json)
  packages/<id>-<version>.vgp        tar.gz: в корне manifest.json и assets/
  previews/<id>/image.webp           картинка для галереи
  previews/<id>/1.opus …             фразы, если есть
  index.html, site.css, site.js      страница каталога
```

В ленте у каждого пакета — `sha256` и `size` архива (шлюз сверяет их до распаковки), `needs` — модели, под которые
у персонажа есть снимки (`optional: true`: без них он говорит запасным голосом), `minGateway` — с какой версии шлюза
(по умолчанию `0.1.0` — каталог вошёл в шлюз этой версии; пакет может задать свой в манифесте, если ему нужно
то, чего старый шлюз не понимает), `verified: true`. Адреса — относительные, от самой ленты. Архивы одинаковы от сборки к сборке; `updatedAt` —
время последнего коммита, если рабочая копия чистая (или `SOURCE_DATE_EPOCH`), иначе — время сборки.

## Посмотреть локально

```bash
node tools/build.mjs
python3 -m http.server 8780 --bind 127.0.0.1 -d dist
# http://127.0.0.1:8780/
```

Из файла (`file://`) страница ленту не прочтёт — нужен веб-сервер. Страница ничего не грузит извне; адрес шлюза для
кнопки «Установить в свой шлюз» спрашивает один раз и хранит только в этом браузере (по умолчанию
`http://localhost`). Кнопка ведёт в пульт: `<адрес шлюза>/panel/#/mind/characters/<id>?install` — пульт откроет
карточку персонажа и окно установки (ссылки внутрь пульта — этап 5 плана персонажей).

## Шлюз и этот каталог

Шлюз берёт ленту по ссылке, вшитой при сборке выпуска (`DUOWAVE_PACKAGES_FEED`), или из `.env`:

```bash
PACKAGES_FEED_URL=http://127.0.0.1:8780/catalog.json   # свой каталог — для проверки локальной сборки
PACKAGES_FEED_URL=off                                  # не ходить в сеть за каталогом
```

Адрес — HTTPS; HTTP — только `localhost` и `127.0.0.1` (для разработки). Архивы и превью шлюз берёт только с того же
источника, что и лента (схема, хост, порт), — поэтому всё лежит рядом. Чтение каталога и установка в шлюзе — этап 2
плана персонажей.

## Публикация (ещё не сделана)

Пока каталог только локальный. Когда владелец решит:

1. Отдельный открытый репозиторий `duowave-packages` на GitHub, ветка `main`.
2. GitHub Pages из Actions (Settings → Pages → Source: GitHub Actions) и файл `.github/workflows/pages.yml`:

   ```yaml
   name: pages
   on:
     push:
       branches: [main]
   permissions:
     contents: read
     pages: write
     id-token: write
   concurrency:
     group: pages
     cancel-in-progress: true
   jobs:
     build:
       runs-on: ubuntu-latest
       steps:
         - uses: actions/checkout@v4
         - uses: actions/setup-node@v4
           with:
             node-version: 22
         - run: node tools/build.mjs
         - uses: actions/upload-pages-artifact@v3
           with:
             path: dist
     deploy:
       needs: build
       runs-on: ubuntu-latest
       environment:
         name: github-pages
         url: ${{ steps.deployment.outputs.page_url }}
       steps:
         - id: deployment
           uses: actions/deploy-pages@v4
   ```

3. Свой домен: Settings → Pages → Custom domain — `packages.duowave.app`, затем Enforce HTTPS. В DNS duowave.app —
   запись `CNAME packages → <владелец>.github.io`.
4. Адрес ленты — **`https://packages.duowave.app/catalog.json`**, навсегда: он вшит в выпуски шлюза, и колонки, которые
   не обновились, ходят по нему. Если каталог когда-нибудь переедет, старый адрес должен отдавать 301 с тем же путём,
   а ссылки в `catalog.json` — оставаться относительными (их проверяют «с того же адреса»). Вшивается он при
   сборке выпуска шлюза: `DUOWAVE_PACKAGES_FEED` в `.github/workflows/release.yml`.

## Правила каталога

- **Голоса — только синтетические** (`voiceOrigin: "synthetic"`, голос по описанию — ничей) **или дикторов с
  письменным согласием** (`"consent"`; само согласие передаётся нам отдельно и в репозиторий не кладётся). Клонов
  реальных людей — актёров, знаменитостей, персонажей фильмов — в каталоге нет и не будет. Записей чужих голосов в
  репозитории нет.
- **Своя графика и свои персонажи**: никаких чужих героев, логотипов и отсылок к фильмам.
- **Без Яндекса и Алисы** — ни в промтах, ни в описаниях, ни на картинках, ни на сайте. Имя слова-активации шлюз
  подставляет сам. Проверка сборки ищет эти названия в текстах пакета.
- **Пока нет подписи — только пакеты без кода** (персонажи, темы). Плагины и приложения — после этапа 8.
- **Всё — через pull request и нашу проверку.** Смотрим промт внимательно: у «Мозга» шлюза есть инструменты (умный
  дом, MCP), и подложить через персонажа можно только промт. Слушаем голос, смотрим картинку. Принятое в `main`
  попадает в ленту с `verified: true`; пакеты не из нашего каталога пульт помечает «не из каталога».
- **Изменили пакет — поднимите `version`.** Шлюз предлагает обновление по версии и перед обновлением показывает, что
  поменялось в характере.
- **Лицензия пакетов — CC BY-NC 4.0, некоммерчески** (поле `license` в манифесте и в ленте): веса OmniVoice — CC BY-NC
  4.0, у CosyVoice 3 — «для академических целей».

## Подпись — этап 8, позже

Сейчас лента — статические файлы по HTTPS без подписи; целостность архивов — через `sha256` и `size` в ленте. Подпись
добавится отдельным этапом, когда каталог будет выложен: файл подписи рядом с лентой делает CI этого репозитория
(сервера по-прежнему нет), ключ — свой у каталога (`packages.pub` в шлюзе), отдельно от ключа выпусков шлюза. Формат
ленты и архивов для этого не меняется. После подписи в каталог смогут прийти плагины и приложения.
