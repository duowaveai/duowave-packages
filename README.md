# Каталог пакетов DuoWave

> Как сделать своего персонажа — коротко, с примерами: [docs/character.md](docs/character.md).

Общий каталог пакетов для голосового шлюза DuoWave: персонажи, приложения и плагины, со временем — темы пульта. Вид
пакета — поле `kind`; в каталоге только то, что проверено нами (`verified`). Пакеты с кодом — приложения и плагины —
идут только в подписанную ленту (ниже, «Приложения» и «Подпись»).

Каталог — статика, сервера нет: лента `catalog.json`, архивы пакетов `.vgp`, превью (картинка и фразы) и страница-
галерея. Шлюз скачивает ленту, показывает каталог в пульте и ставит пакет только по кнопке человека с правом — сам
ничего не ставит и не обновляет. Замысел и формат — `docs/plans/characters.md` в репозитории шлюза (разделы 1–3, 7 и
«Контракт API»); этот репозиторий — его этапы 1 и 6.

## Что внутри

```
packages/<id>/            пакет: то, что попадёт в архив
  manifest.json           кто это, характер, регуляторы тона, голос
  assets/                 аватар, фразы-пробники, снимки голоса, образец голоса
art/<id>.svg              исходник аватара (в пакет не идёт: SVG в пакетах нельзя)
voices.json               описание голоса каждого персонажа для tools/design.py
schemas/                  JSON Schema: ленты (catalog.schema.json), манифеста персонажа и приложения
tools/
  check.mjs               проверка пакетов (её же вызывает сборка)
  build.mjs               сборка dist/: архивы, превью, хеши, catalog.json, сайт
  tar.mjs                 tar.gz без зависимостей, одинаковый от сборки к сборке
  avatars.mjs             art/<id>.svg → packages/<id>/assets/avatar.webp
  design.py               голоса по описанию (OmniVoice) → снимки и фразы в пакет
  pin.mjs                 рекомендовать пакет чужой ленты: хеш его архива → feed.config.json
site/                     страница каталога (HTML, CSS, JS без фреймворков); сборка кладёт её в dist/
dist/                     результат сборки, в git не хранится
work/                     черновики голосов (варианты, отпечатки), архивы из tools/pin.mjs; в git не хранится
```

## Пакет персонажа

Обычный пакет шлюза без кода: `manifest.json` и `assets/`. Схема — `schemas/character-manifest.schema.json`, пример —
любой из `packages/*/manifest.json`. Коротко:

- `schema: 1`, `kind: "character"`, `id` (как папка), `version` (semver), `api: "^1"`, `title`, `description`,
  `runs` (`pc`, `station`, `stationServer`), `license`;
- `contributes.characters` — список (обычно один персонаж): `id`, `gender` (`male` | `female` | `any`), `color`,
  `avatar`, `prompt`, `tones`, `samples`, `fallbackVoice`, `voices`, `ref`, `voiceOrigin` (`synthetic` | `consent`);
- `tones` — регуляторы: у каждого 2–5 положений, каждое подставляет в промт одну строку `line`; `default` — номер
  положения с нуля;
- `voices` — снимки голоса по id модели (`omnivoice`, `cosyvoice3`): `{file, model}`, где `model` — ревизия весов;
  `ref` — образец WAV и его слова, из которых шлюз переснимет голос под другую ревизию.

Пределы (проверяет `tools/check.mjs`): промт — до 4000 знаков; аватар — WebP или PNG, квадрат, до 256 КБ; фраз-
пробников — не больше трёх, Opus до 64 КБ каждая; пакет целиком — меньше 1 МБ; все пути — внутри `assets/`, без `..`
и ссылок; SVG нельзя; только `manifest.json` и `assets/` — никакого кода; в текстах нет «Алисы» и «Яндекса».

Промт описывает только персонажа: кто он, как говорит, в каком роде, чего никогда не делает. Строку про слово-
активацию колонки и правила речи (коротко, без списков, числа словами) шлюз добавляет сам.

## Как добавить персонажа

1. Скопируйте папку любого персонажа в `packages/<id>/` (id — строчные латинские буквы, цифры и «-», с буквы) и
   перепишите `manifest.json`: id, тексты, цвет, регуляторы, запасной голос подходящего пола. Голоса — пустые:
   `"samples": []`, `"voices": {}`, без `ref`.
2. Нарисуйте аватар в `art/<id>.svg` (512×512, своя графика — никаких чужих персонажей и реальных людей) и
   переведите в WebP: `node tools/avatars.mjs <id>`. ImageMagick рисует обводки, только если у них явно указано
   `stroke-opacity="1"`.
3. Опишите голос в `voices.json`: `instruct`, фраза образца `reference`, три фразы `samples`.
4. Проверьте и соберите: `node tools/build.mjs`. Ошибки названы словами — поправьте и повторите.
5. Pull request. Голос делается отдельно (ниже) — пакет без голоса тоже годен.

## Приложения

Приложение (`kind: "app"`) — своя программа рядом со шлюзом: шлюз запускает её под надзором, зовёт её функции по HTTP
и даёт ей Host API 2. Как его писать — `docs/plugins/AUTHORING.md` в репозитории шлюза, разделы «Приложения» и
«Приложение на Node»; пример — `docs/plugins/apps/hello-node/` там же. Схема манифеста —
`schemas/app-manifest.schema.json`, точнее схемы — `tools/check.mjs`: он повторяет правила шлюза
(`gateway/src/plugins/manifest.rs`) и проверяет файлы.

Что несёт пакет приложения на Node (`"runtime": "node"`):

```
packages/<id>/
  manifest.json        kind: app, runtime: node, api: "^2", runs: ["pc"], права, бюджет, вклады
  server.mjs           скрипт, который запускает шлюз (node.entry; по умолчанию index.js) — и остальной код
  package.json         если есть зависимости
  package-lock.json    по нему шлюз ставит их сам: npm ci --ignore-scripts --omit=dev
  panel.js, assets/…   окно в пульте, картинки, шрифты — по желанию
```

- **Манифест** — по правилам шлюза: `api: "^2"`; `runs` у приложения на Node — только `pc` (на колонке Node нет);
  `budget.memoryMb` — до 1024 у Node (до 64 у остальных), `budget.filesMb` — до 4096, `budget.tasks` — от 1 до 4;
  права — только `net:<хост>` и связи шины `see:`/`listen:`/`call:`/`edit:<адрес>` (слова Host API 1 — ошибка с
  подсказкой, чем они стали); `health`, `settings` (ключ API — с `"secret": true`; без которой приложение работает — с
  `"optional": true`: пульт пишет «можно не заполнять»), `contributes` (фразы, инструменты,
  источники, события, ритмы, шина, пульт), `prefer: "home"`. Плюс правила каталога: `title`, `description` и
  `license` обязательны, в текстах нет «Алисы» и «Яндекса».
- **Код на месте**: файл `node.entry` есть в пакете.
- **Без `node_modules/`.** Зависимости шлюз ставит сам — по `package-lock.json`, без сценариев установки. Поэтому: если
  `package.json` называет зависимости, рядом обязательно `package-lock.json` (npm 7+, `lockfileVersion` 2 или 3), он
  сходится с `package.json`, и каждый пакет в нём — из `https://registry.npmjs.org/` с `integrity`; ссылок на папки и
  рабочих областей нет. Пакет со сценарием установки (`hasInstallScript`) проверка называет предупреждением: сценарий
  не запустится, годится такой пакет, только если у него готовые сборки под все системы.
- **Пределы**: распакованный пакет — до 32 МБ, архив — до 16 МБ, файлов — до 500, путь — до 100 байт, `manifest.json` —
  до 64 КБ; SVG нельзя (и под другим расширением); ссылок, скрытых файлов и папок нет.

Приложение со своими сборками (`"runtime": "process"`) несёт `targets` — файл и SHA-256 под каждую платформу
(`darwin-arm64`, `linux-aarch64`, `linux-x86_64`); проверка сверяет хеши с файлами. В ленте у него архив под каждую
платформу (`platforms`, в архиве только её сборка) — шлюз берёт архив своей; общий архив со всеми сборками — если
влезает в пределы. Плагин (`kind: "plugin"`, код в шлюзе: `backend.js`, `backend.wasm` или MCP) проверяется и
собирается по тем же правилам. `"resident": true` — программа работает всё время, пока приложение включено (приёмник,
которого телефон находит сам); шлюзы до 0.13.0 поля не знают, поэтому с ним — `minGateway` не ниже 0.13.0.

Первое такое приложение — `packages/airplay/` (AirPlay на колонке, `runs: ["station"]`). Его исходник — не здесь, а
в репозитории шлюза (`apps/airplay/`: программа говорит протоколом шлюза и меняется вместе с ним); здесь — собранный
файл, лицензии, `NOTICE` и `SOURCE.md` (где исходники и как пересобрать, этого требует LGPL декодера AAC). Новая сборка
— `sh apps/airplay/build.sh <этот каталог>/packages/airplay` в репозитории шлюза: файл, версия и SHA-256 в манифесте
обновятся сами. Каждая версия добавляет в историю git около 11 МБ. Значок — `art/airplay.svg` (свой знак, не значок
Apple), `node tools/avatars.mjs airplay` кладёт его в `assets/avatar.webp`.

Значок приложения или плагина — `"icon": "avatar.webp"` в манифесте: квадратная WebP или PNG в `assets/` (128–1024
точек, до 256 КБ). Сборка кладёт её превью пакета (`preview.image`) — MagicPlace показывает её на карточке, а стол
пульта — на ярлыке. Без значка — цветная плитка с первой буквой.

**Проверка — как у персонажей: pull request и наша проверка кода.** Читаем код целиком: куда он ходит (права `net:`),
до чего в доме дотягивается (связи шины), что ставит из `package-lock.json`. Принятое в `main` попадает в ленту с
`verified: true` — но только подписанной: песочницы у программ приложений нет, приложение на Node работает с правами
пользователя компьютера, поэтому шлюз ставит код из каталога, лишь если подпись ленты сошлась с его ключом каталога
(ниже, «Подпись»).

Страница приложения в каталоге — «Подписано DuoWave» (лента подписана, подпись сошлась), его права до установки и
«собирает компьютер» у приложения, которое работает только на компьютере (`runs: ["pc"]`, все приложения на Node):
работу делает компьютер, а не колонка. Данные для неё — в записи ленты: `runtime`, `runs`, `budget`, `permissions`;
саму страницу рисуют пульт шлюза и сайт каталога (этап 9 плана «Ленты» в шлюзе — `docs/plans/feed.md`).

## Голоса персонажей: `tools/design.py`

Голоса синтетические — по описанию, ничьи. Модель — OmniVoice в режиме voice design: описание вида
`male, elderly, low pitch` (пол, возраст, высота голоса, шёпот, акцент) → десяток вариантов одной фразы → лучший на
слух становится образцом → `clone-server/imprint.py` шлюза снимает с него снимки под каждую модель.

Нужно: шлюз рядом (`../voice-gateway-server`) с установленной моделью OmniVoice (пульт шлюза → «Модели» → «Голос»);
для снимка под CosyVoice 3 — и она; `ffmpeg` с libopus. Работает на видеокарте Мака (MPS) или NVIDIA, занимает минуты
и несколько гигабайт памяти. Запускается окружением модели — своих зависимостей у скрипта нет:

```bash
CS=../voice-gateway-server/clone-server          # или --clone-server / CLONE_SERVER
PY=$CS/runtime/omnivoice/env/bin/python

# 1. варианты: 10 штук фразы образца из voices.json → work/arthur/candidates/
$PY tools/design.py candidates arthur
$PY tools/design.py candidates arthur --instruct "male, elderly, moderate pitch" --count 5   # ещё, с другим описанием
open work/arthur/index.html                      # послушать; у каждого — длина и годится ли он в образец

# 2. выбранный вариант → пакет
$PY tools/design.py adopt arthur 7

# 3. послушать packages/arthur/assets/samples/*.opus, собрать, закоммитить
node tools/build.mjs
```

`adopt` делает:

- снимки `imprint.py` под каждую установленную модель (`omnivoice`, `cosyvoice3`; `--engines` — выбрать самому), на
  процессоре — так вдвое меньше памяти (`--imprint-device`); образцом берётся весь вариант целиком, его слова уже
  известны — распознавание не нужно (imprint.py спрашивает их у маленького сервера слов внутри design.py);
- `assets/voices/ref.wav` — тот кусок, с которого сняты снимки, `assets/voices/<модель>.pt` — снимки;
- до трёх фраз-пробников голосом первой модели → `assets/samples/N.opus`;
- в манифесте — `voices` (файл и ревизия весов: OmniVoice — из кеша HuggingFace, CosyVoice 3 — коммит его
  репозитория), `ref` (файл и слова), `samples`; в `voices.json` — `adopted`: номер, зерно и описание варианта.

Модели, которой нет на этом компьютере, в пакете не будет — шлюз снимет снимок сам из `ref.wav`, когда она встанет.
Варианты повторяемы: у каждого своё зерно (`--seed`), разнообразие — `--temperature`, темп — `--speed`. Уже
опубликованному пакету с новым голосом — новая `version`.

## Сборка

```bash
node tools/build.mjs            # проверить пакеты и собрать dist/ — без пакетов с кодом
node tools/build.mjs --signed   # то же с приложениями и плагинами: только когда ленту подпишут (CI)
node tools/build.mjs --check    # только проверить
node tools/check.mjs            # то же, с выбором пакетов: node tools/check.mjs packages/arthur
```

Нужен только Node 18+ — зависимостей нет. Пакет с ошибкой не собирается, и каталог целиком тоже. Пакеты с кодом
проверяются всегда, а в ленту идут только с `--signed`: без него сборка называет каждый, что оставила за бортом. Своя
лента (`feed.config.json` с `own`) кода не несёт никогда — из своих источников шлюз его не ставит. Результат:

```
dist/
  catalog.json                       лента (схема — schemas/catalog.schema.json)
  packages/<id>-<version>.vgp        tar.gz: в корне manifest.json и файлы пакета
  packages/<id>-<version>-<платформа>.vgp   у приложения со сборками — архив под каждую платформу
  previews/<id>/<version>/image.webp картинка для галереи (папка по версии: новая версия — новый адрес)
  previews/<id>/<version>/1.opus …   фразы, если есть
  index.html, site.css, site.js      страница каталога
```

В ленте у каждого пакета — `sha256` и `size` архива (шлюз сверяет их до распаковки), `needs` — модели, под которые
у персонажа есть снимки (`optional: true`: без них он говорит запасным голосом), `minGateway` — с какой версии шлюза
(по умолчанию `0.1.0` — каталог вошёл в шлюз этой версии; пакет может задать свой в манифесте, если ему нужно
то, чего старый шлюз не понимает), `verified: true`. У пакета с кодом ещё `runtime`, `budget` (`memoryMb` — шлюз
сверяет его со свободной памятью колонки, `filesMb` — место его папки), `permissions` и у приложения со сборками
`platforms`; `minGateway` — не ниже 0.7.0 (Host API 2), у приложения на Node — не ниже 0.9.0 (выпуск, где появился
`runtime: node`). Адреса — относительные, от самой ленты. Архивы одинаковы от сборки к сборке; `updatedAt` —
время последнего коммита, если рабочая копия чистая (или `SOURCE_DATE_EPOCH`), иначе — время сборки.

Для MagicPlace — магазина в пульте шлюза 0.9.0 (старые шлюзы эти поля пропускают, `format` остаётся `1`):

- `faces` — лица приложения, сборка выводит их из манифеста: `widget` (карточки `contributes.panel.cards`, слот
  `desk.widgets` в манифесте или в `panel.js`), `skill` (фразы `intents` или инструменты `tools`), `window`
  (`contributes.panel.sections`), `schedule` (`contributes.schedules`). У персонажа и темы поля нет.
- `recommended: true` — у пакетов из списка `recommended` в `feed.config.json`: ряд «Рекомендуем» и шаг первого
  запуска. Рекомендует каталог, а не автор пакета; из своих источников шлюз пометку не берёт.
- `unlisted: true` — у пакетов из списка `unlisted` в `feed.config.json`: лента держит пакет скрытым (шлюз новее
  0.11.1). Он целиком в ленте и ставится, но в MagicPlace, каталоге персонажей, голосом и на странице каталога его не
  видно, пока администратор не включил в пульте скрытую возможность «Показывать скрытые пакеты» (восемь нажатий на
  «Для разработчиков»); поставленный остаётся на виду. Не вместе с `recommended` и `hidden`: `hidden` убирает пакет у
  всех и выключает поставленный. Старые шлюзы поле пропускают.
- `addedAt` — когда пакет появился в каталоге: время первого коммита его `manifest.json`. Нужна вся история git
  (в CI — `fetch-depth: 0`); без неё поля нет, и ряд «Новое» пуст.
- `downloads` — что приложение скачает само, кроме архива: `[{ id, title, mb, when }]`, `when` — `install` или
  `first-use`, переводы названий — `locales.<код>.downloads.<id>`. Берётся из такого же поля манифеста. Node шлюза
  туда не пишется: шлюз сам знает, есть ли он у него.

Рекомендовать пакет чужой ленты — своего источника, который человек добавляет по ссылке, или ленты партнёра — можно
только отсюда, из главной ленты: сама чужая лента себя не рекомендует, шлюз это поле у неё пропускает. В
`feed.config.json` — список `recommends`: адрес той ленты, `id` пакета и `sha256` его архива, который мы посмотрели
(из её `catalog.json`):

```json
{ "recommends": [{ "feed": "https://example.org/catalog.json", "id": "storyteller", "sha256": "…64 знака…" }] }
```

Сборка кладёт список в ленту полем `recommends` верхнего уровня. Шлюз метит такой пакет «рекомендуем» и «проверен»,
только если человек этот источник у себя добавил и хеш архива тот же: поменяли архив — пометки нет, пока мы не
посмотрим новый и не впишем его хеш. Код из чужих лент так не ставится; в своей ленте (`own`) поля нет. Лента, которой
мы доверяем целиком, называется в `feeds.json` с `verified: true` — тогда её собственные `recommended` действуют сами.

Хеш руками не переписывают — строку вписывает `tools/pin.mjs`. Он скачивает ту ленту и архив пакета, сверяет хеш,
кладёт архив в `work/pins/` (что внутри — `tar -tzf`) и называет пакет, версию и чей голос у персонажа; пакет с кодом
не закрепляет. Без адреса он проверяет все закреплённые: поменялся архив в той ленте — скажет, и после просмотра
пакет закрепляют заново той же командой. Потом каталог публикуется как обычно; новый выпуск шлюза не нужен — шлюзы
берут список при следующем чтении ленты.

Адрес ленты, которую не раскрываем (демо, которое показываем лично), в открытый каталог не пишут: `--no-feed`
закрепляет пакет без него — в строке только `id` и `sha256`. Такая строка — один архив: шлюз (новее 0.11.0) метит его в
любой добавленной ленте, если хеш тот же; старые шлюзы строку пропускают. Адрес остаётся здесь, в
`work/pins/feeds.json` (не в git), — по нему `node tools/pin.mjs` проверяет и такие строки.

```bash
node tools/pin.mjs https://example.org/catalog.json storyteller            # закрепить (или обновить хеш)
node tools/pin.mjs --no-feed https://example.org/d-…/catalog.json demo    # закрепить без адреса ленты в каталоге
node tools/pin.mjs                                                         # закреплённые: тот ли архив сейчас
node tools/pin.mjs --remove https://example.org/catalog.json storyteller   # убрать
```

## Посмотреть локально

```bash
node tools/build.mjs
python3 -m http.server 8780 --bind 127.0.0.1 -d dist
# http://127.0.0.1:8780/
```

Из файла (`file://`) страница ленту не прочтёт — нужен веб-сервер. Страница ничего не грузит извне; адрес шлюза для
кнопки «Установить в свой шлюз» спрашивает один раз и хранит только в этом браузере (по умолчанию
`http://localhost`). Кнопка ведёт в пульт: `<адрес шлюза>/panel/#/mind/characters/<id>?install` — пульт откроет
карточку персонажа и окно установки (ссылки внутрь пульта — этап 5 плана персонажей).

## Шлюз и этот каталог

Шлюз берёт ленту по ссылке, вшитой при сборке выпуска (`DUOWAVE_PACKAGES_FEED`), или из `.env`:

```bash
PACKAGES_FEED_URL=http://127.0.0.1:8780/catalog.json   # свой каталог — для проверки локальной сборки
PACKAGES_FEED_URL=off                                  # не ходить в сеть за каталогом
```

Адрес — HTTPS; HTTP — только `localhost` и `127.0.0.1` (для разработки). Архивы и превью шлюз берёт только с того же
источника, что и лента (схема, хост, порт), — поэтому всё лежит рядом. Чтение каталога и установка в шлюзе — этап 2
плана персонажей.

     deploy:
       needs: build
       runs-on: ubuntu-latest

         name: github-pages

3. Свой домен: Settings → Pages → Custom domain — `packages.duowave.app`, затем Enforce HTTPS. В DNS duowave.app —

## Два источника пакетов: сообщества и наши (на будущее)

Решено 11.11.2026, пока ничего из этого не сделано. Шлюз знает **один** вшитый адрес ленты, и он не меняется: два
источника складываются в одну ленту, а не в две ссылки.

- **Сообщество** — этот открытый репозиторий: пакеты приходят pull request'ами, мы проверяем и принимаем.
- **Наши** — отдельный закрытый репозиторий, когда в нём появятся пакеты. Сборка каталога берёт пакеты из обоих и
  выкладывает **одну** ленту и все архивы на `packages.duowave.app`. Шлюз при этом не меняется.
- Закрытым у «наших» остаются только исходники и работа над пакетом: опубликованный архив может скачать любой —
  шлюзу его нужно скачать без входа.
- В ленте у пакета можно будет пометить, чей он (например, поле `publisher`: DuoWave или сообщество), чтобы пульт
  показывал это человеку. Шлюз пропускает незнакомые поля ленты, так что старые выпуски это не ломает.

Что соблюдать уже сейчас, чтобы потом ничего не переделывать:

- **`id` пакетов — один на оба источника.** Два разных пакета с одним `id` шлюз не различит. Перед приёмом пакета
  проверять, что `id` не занят и не зарезервирован под наш.
- **`format: 1` в ленте не менять.** Шлюз читает только `format: 1`: лента другого формата у старых выпусков
  перестанет открываться целиком. Новое — только новыми необязательными полями.
- **Все архивы и превью — на том же адресе, что и лента** (`packages.duowave.app`). Шлюз не скачает их с другого
  хоста; чтобы разрешить другой хост, нужна доработка шлюза, и старые выпуски её не получат.
- **Код — только после подписи (этап 8)**, неважно, наш пакет или чужой.

Если понадобится отдельная лента (другой хост, другой владелец), в главную ленту добавляется необязательное поле со
ссылками на дополнительные ленты. Новые выпуски шлюза пойдут и туда, старые его пропустят и останутся с главной.
Вшитый адрес при этом не меняется.

**Закрытые и платные пакеты**, которые ставит не каждый, — отдельная задача, её пока не закладываем. Для них нужны
учётные записи и проверка доступа (шлюз представляется, сервер решает, отдать ли архив), а это пересекается с будущими
`my.` и `auth.`. Шлюз под это дорабатывается в любом случае, поэтому заранее угадывать формат смысла нет.

## Правила каталога

- **Голоса — только синтетические** (`voiceOrigin: "synthetic"`, голос по описанию — ничей) **или дикторов с
  письменным согласием** (`"consent"`; само согласие передаётся нам отдельно и в репозиторий не кладётся). Клонов
  реальных людей — актёров, знаменитостей, персонажей фильмов — в каталоге нет и не будет. Записей чужих голосов в
  репозитории нет.
- **Своя графика и свои персонажи**: никаких чужих героев, логотипов и отсылок к фильмам.
- **Без Яндекса и Алисы** — ни в промтах, ни в описаниях, ни на картинках, ни на сайте. Имя слова-активации шлюз
  подставляет сам. Проверка сборки ищет эти названия в текстах пакета.
- **Код — только в подписанной ленте.** Приложения и плагины сборка кладёт в ленту только с `--signed`, а CI зовёт её
  так, только когда подпишет `catalog.json` (ниже, «Подпись»). Код проходит нашу проверку, как персонажи, — pull
  request (выше, «Приложения»).
- **Всё — через pull request и нашу проверку.** Смотрим промт внимательно: у «Мозга» шлюза есть инструменты (умный
  дом, MCP), и подложить через персонажа можно только промт. Слушаем голос, смотрим картинку. Принятое в `main`
  попадает в ленту с `verified: true`; пакеты не из нашего каталога пульт помечает «не из каталога».
- **Изменили пакет — поднимите `version`.** Шлюз предлагает обновление по версии и перед обновлением показывает, что
  поменялось в характере.
- **Лицензия пакетов — CC BY-NC 4.0, некоммерчески** (поле `license` в манифесте и в ленте): веса OmniVoice — CC BY-NC
  4.0, у CosyVoice 3 — «для академических целей».

## Где что работает — `reach.json`

Для «Выхода в интернет» шлюза (приложение «VPN»): из каких стран сервис не работает. `services` — поставщики «Мозга»,
слуха и голоса, MCP-инструменты и Алиса по id (`provider:openai`, `system:alice`) с их адресами (`hosts`) — уходят
файлом `dist/reach.json` рядом с лентой; `apps` — по id пакета — ложатся в запись пакета ленты полем `reach`. Только
`blocked` (откуда не работает) или `only` (откуда только), коды стран ISO, без слов. Сверяем руками раз в месяц и по
жалобам, `updatedAt` — дата сверки. Подписывается тем же ключом, что лента:
`scripts/sign-catalog.sh dist/reach.json` (шлюз с ключами без подписи файл не берёт — работает на своей копии).

## Подпись

Ленту подписывает CI этого репозитория (`.github/workflows/pages.yml`, сервера по-прежнему нет): с ключом каталога в
секретах репозитория (`PACKAGES_SECRET_KEY` — файл секретного ключа minisign, `PACKAGES_KEY_PASSWORD` — его пароль)
он собирает ленту с `--signed`, кладёт рядом `catalog.json.minisig` и сверяет подпись с `packages.pub`. В
`packages.pub` — открытые ключи каталога, те же, что встроены в каждый выпуск шлюза (`gateway/packages.pub`):
выпускной и запасной, который хранится офлайн на день, когда выпускной потерян или утёк. Подпись любым из них годится —
и здесь, и в шлюзе, поэтому переход на запасной — это смена секретов, а не нового шлюза. Ключ каталога — свой,
отдельно от ключа выпусков шлюза.

Подпись не сошлась ни с одним ключом — сборка падает и прежняя лента остаётся. Секретов нет — лента собирается без
пакетов с кодом и без подписи, с предупреждением в журнале CI; персонажи и темы ставятся и из неё. Целостность архивов
— как и прежде, через `sha256` и `size` в ленте, а их саму держит подпись. Формат ленты и архивов от подписи не
меняется.
